# 机会发现：场景池与"是否值得做"闸门

## R — Reading (原文)

> 「顶部输入项：战略目标、业务痛点、一线反馈、客户需求、技术机会。→ **场景池** →
> **场景梳理** → **是否值得做**（判断）— 否 → **暂缓 / 观望**；是 → 进入下一阶段。」
> —— 一图讲透 FDE（Simon的数据笔记），机会发现阶段

## I — Interpretation (自述)

机会发现回答"**有哪些事值得用AI做**"。图的解法是一个漏斗：

1. **五个入口**并行收集：战略目标（自上而下）、业务痛点（自上而下）、一线反馈
   （自下而上）、客户需求（外部）、技术机会（技术推力）。五个入口缺一不可——
   只从战略出发会脱离一线，只听一线会碎片化。
2. **场景池**：所有候选先入池，不评判。场景池把"AI落地"从口号变成一张可管理的清单。
3. **场景梳理**：对池内场景做初步归并、去重、补充上下文。
4. **是否值得做闸门**：逐个判断。判否的走"暂缓/观望"——注意不是删除，是留观。
   判是的才进入方案定义。

这条闸门是整个框架的第一道成本控制：把有限资源集中到值得做的场景，其余显式
挂起。方向乱的问题在源头就被处理掉了。

## E — Execution (可执行步骤)

**输入契约**：至少1个入口的输入（理想为五入口各若干条）；可选：现有项目清单。
什么都没有时，先按五入口各出3个引导式问题采集，不得凭空编造企业情况。

1. **五入口采集**：按战略目标/业务痛点/一线反馈/客户需求/技术机会五列建表，
   每列列出现有素材；缺哪列，向用户提问补齐。完成标准：五列均有内容或显式标注"入口缺失"。
2. **建场景池**：把素材翻译成"动词+对象+AI能力"格式的场景句（如"用预测模型
   优化门店补货量"），全部入池，不评判。完成标准：池内每条场景可追溯到至少一个入口。
3. **场景梳理**：合并同类、拆分混合场景、补全上下文（涉及角色/系统/数据）。
4. **是否值得做闸门**：对每条场景，按四问打分——战略对齐？痛点真实且高频？
   数据可得？ROI量级合理？四问中≥3个"是"→通过；否则标注"暂缓/观望"+一句理由。
5. **输出契约**：场景池表格（场景 / 来源入口 / 闸门判定 / 判定理由 / 下一步）。
   通过项进入 fde-solution-definition；挂起项保留在池中。

## B — Boundary (边界)

- **不要**用于：已经立项、在为既有项目做方案细化（那是下一阶段）；单场景深挖。
- **失败模式**：只有自上而下入口（场景脱离一线）；闸门形同虚设（全部通过=
  没有筛选）；把"暂缓"当"否决"删掉（图明确是"暂缓/观望"，留观不是毙掉）。
- **作者盲点**：图未给出闸门判定的具体评分标准，本卡的"四问"是执行层补全
  （已在E段显式标注为约定）；图也未处理入口之间冲突的场景（战略要、一线不要），
  实践中需引入决策人机制。

## Purpose

机会发现回答"有哪些事值得用AI做"。五个入口并行喂场景池，逐个过"是否值得做"四问闸门——通过项进入方案定义，判否项显式"暂缓/观望"（留观不删除）。这是FDE框架的第一道成本控制，把有限资源集中到值得做的场景，在源头收敛"AI落地方向太乱"的问题。

1. 按**五入口**（战略目标/业务痛点/一线反馈/客户需求/技术机会）建表采集素材；缺列则向用户提问补齐，不凭空编造。
2. 把素材翻译成"动词+对象+AI能力"场景句，全部入池不评判，每条可追溯到至少一个入口。
3. 场景梳理：合并同类、拆分混合场景、补全角色/系统/数据上下文。
4. 逐条过**四问闸门**（战略对齐？痛点真实且高频？数据可得？ROI量级合理？≥3个"是"→通过；否则"暂缓/观望"+一句理由）。
5. 输出场景池表格（场景/来源入口/判定/理由/下一步）；通过项进入 fde-solution-definition，挂起项留在池中。
   详细执行契约（输入契约、完成标准）见 `## E — Execution (可执行步骤)`。

## Limitations

- 不用于已立项、为既有项目做方案细化的场景（那是 fde-solution-definition 的输入），也不做单场景深挖。
- 图未给出闸门评分标准，"四问"是本卡显式标注的执行层补全；入口冲突（战略要、一线不要）需引入决策人机制，图未处理。
- 失败模式：只有自上而下入口（脱离一线）；闸门全部通过=没有筛选，形同虚设。
- 原素材未提供实际案例，A1示例为明确标记的合成演练。

## Troubleshooting

- **闸门判定全部通过** → 闸门形同虚设，说明判定过松；按四问严格打分，<3个"是"必须标"暂缓/观望"。
- **场景脱离一线** → 只有自上而下入口所致；补齐一线反馈/客户需求入口，缺列时向用户提问采集。
- **想直接淘汰"暂缓"场景** → 错误——图明确是"暂缓/观望"而非否决，挂起项必须保留在池中留观。
- **没有任何输入素材** → 不得凭空编造企业情况；先按五入口各出3个引导式问题采集。
