# FDE三阶段落地主流程（机会发现→方案定义→执行落地）

## R — Reading (原文)

> 「整体结构为三大阶段纵向排列：机会发现阶段（橙色）→ 方案定义阶段（蓝色）→ 执行落地阶段（绿色），各阶段间用箭头连接，内部含判断分支与回环反馈。」

## I — Interpretation (自述)

这张图的主干是一条纵向三段式流程：

1. **机会发现阶段**（橙色）：从战略目标、业务痛点、一线反馈、客户需求、技术机会
   五个入口收集素材，汇入"场景池"，经"场景梳理"后过一道 **是否值得做** 的闸门——
   否则暂缓/观望，是则进入下一段。
2. **方案定义阶段**（蓝色）：把选中的场景定义到可执行——价值评估、优先级排布、
   目标定义（成功指标）、流程拆解、数据准备、方案设计，六项产出后过 **是否可行**
   闸门（否则调整范围回环），通过后做试点规划、资源协同、实施计划。
3. **执行落地阶段**（绿色）：环境准备 → 能力构建 → 联调测试 → **效果达标？** →
   试点运行 → **试点通过？** → 规模化推广 → 上线运营 → 运营反馈 → 持续优化；
   两道执行闸门各带修正/迭代回环。

三段之间的顺序是刚性的：**没有通过前一道闸门，不进入下一段**。整条主流程由左侧
"风险处理/人工兜底"旁路全程护航。FDE 的价值主张正在于此：把"AI落地"从一次性项目
变成一条有闸门、有回环、有兜底的**工程化流水线**。

## E — Execution (可执行步骤)

**输入契约**：企业的战略目标、至少1个候选场景或痛点描述；组织规模与所在行业
（用于判断试点规模）。缺失时先询问，不得假设。

1. **阶段判定**：问三个问题——(a) 是否已有通过验收的在产AI系统？(b) 是否有已
   立项且完成六项定义的方案？(c) 是否只有想法/痛点？
   - 仅 (c) → 从机会发现开始（跳 fde-opportunity-discovery）
   - (c)+(b) → 进入方案定义补全（跳 fde-solution-definition）
   - (a) 或有运行中试点 → 进入执行落地（跳 fde-pilot-execution）
2. **按所处阶段执行对应能力卡**，每道闸门显式判定并记录（值得做？/可行？/达标？/通过？）。
3. **闸门未过**：按图走对应回环（暂缓观望 / 调整范围 / 问题修正 / 优化迭代），
   不得跳段推进。
4. **输出契约**：一张路线图，含：当前所处阶段、下一道闸门及其判定标准、待补的
   定义产物清单、回环触发条件、风险处理与人工兜底安排（引用 fde-risk-human-fallback）。

## B — Boundary (边界)

- **不要**用于：无组织语境的个人AI技巧；纯算法研究；没有决策权的纯咨询闲聊。
- **失败模式**（图的隐含警告）：跳过"是否值得做"直接上项目（方向乱的根源）；
  六项定义不齐就开建（试点必返工）；"效果达标/试点通过"形同虚设（带病上线）。
- **相邻混淆**：与一般项目管理（PMBOK）的区别——本框架每道闸门都以**业务价值
  达成**为判定标准，不是进度/成本三角；与敏捷的区别——回环是闸门驱动的，不是
  时间盒驱动的。

## Purpose

FDE 三阶段落地主流程：机会发现（"是否值得做"闸门）→ 方案定义（六项定义 + "是否可行"闸门）→ 执行落地（"效果达标？"、"试点通过？"两道闸门，之后规模化与运营反馈）。三段顺序刚性——没通过前一道闸门不进入下一段；整条流程由风险处理/人工兜底旁路护航，把 AI 落地从一次性项目变成有闸门、有回环、有兜底的工程化流水线。

5. 输出路线图：当前阶段、下一道闸门及判定标准、待补定义产物清单、回环触发条件、兜底安排（引用 fde-risk-human-fallback）。

## Limitations

- 不适用于：无组织语境的个人 AI 技巧、纯算法研究（训练/微调/RAG 等单点技术是方案定义阶段的内部子问题）、没有决策权的纯咨询闲聊。
- 每道闸门以业务价值达成为判定标准，不是 PMBOK 的进度/成本三角；回环是闸门驱动的，不是敏捷式时间盒驱动。
- 原素材是方法论信息图，未提供实际企业案例；应用示例为明确标记的合成演练。
- 分诊到具体步骤归属、现状基线、价值销售分别见 fde-workflow-triage、fde-process-mapping、fde-system-outcome。

## Troubleshooting

- 错误：方向混乱、多个项目打架。原因：跳过"是否值得做"闸门直接上项目。解决：回到机会发现阶段重新梳理场景池并显式判定闸门。
- 错误：试点反复返工。原因：六项定义不齐就开建。解决：回方案定义阶段补全，"是否可行"逐项判定后再进执行。
- 错误：带病上线。原因："效果达标/试点通过"判定形同虚设。解决：闸门判定必须显式记录；未过即走修正/迭代回环，不得进入规模化。

## Prerequisites

- 无外部工具或 API 密钥要求；兜底安排需引用 fde-risk-human-fallback 卡。
