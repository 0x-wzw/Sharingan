# 执行落地：试点闸门、回环修正与规模化

## R — Reading (原文)

> 「**环境准备** → **能力构建**（← 问题修正）→ **联调测试** → **效果达标？**（判断）
> — 否 → **问题修正**；是 → **试点运行** → **试点通过？**（判断）— 否 → **优化迭代**
> （回环）；是 → **规模化推广** → **上线运营** → **运营反馈** → **持续优化**。」
> —— 一图讲透 FDE（Simon的数据笔记），执行落地阶段

## I — Interpretation (自述)

执行落地阶段有**四步建设、两道闸门、三个回环、一段运营**：

1. **建设**：环境准备（算力/权限/集成环境）→ 能力构建（模型/应用开发，期间随时
   接受问题修正回环）→ 联调测试（端到端打通）。
2. **第一道闸门：效果达标？**——在受控环境里对照成功指标测。不达标 → 问题修正
   回环（回能力构建）；达标 → 试点运行。
3. **第二道闸门：试点通过？**——真实业务环境小范围跑（图把试点规划放在上一
   阶段，这里执行）。不通过 → 优化迭代回环；通过 → 规模化推广。
4. **运营段**：规模化推广 → 上线运营 → 运营反馈 → 持续优化。上线不是终点，
   反馈回环把系统拉进持续改进。

两道闸门的区别要记牢：**效果达标**是技术验收（实验室），**试点通过**是业务验收
（现场）。技术达标而业务不认可的AI系统是最常见的烂尾形态——图用两道独立的门
堵死了这条路。

## E — Execution (可执行步骤)

**输入契约**：过闸的方案定义文档（至少含成功指标、试点规划、角色分工）。缺
成功指标 → 回 fde-solution-definition 补，不得带模糊指标进执行。

1. **环境准备**：列出算力/数据权限/系统集成/安全合规清单并逐项落位。完成标准：
   联调环境可用，数据管道可拉数。
2. **能力构建**：开发模型与应用；出现缺陷 → 走**问题修正**回环（记录：问题/
   修正/验证）。完成标准：功能完整，可进入联调。
3. **联调测试 + 效果达标闸门**：在受控环境按成功指标实测。判据引用方案定义中
   的指标与测量方式。不达标 → 问题修正回环（不得调指标凑数；调指标=变更管理，
   须记录）。达标 → 进试点。
4. **试点运行 + 试点通过闸门**：按试点规划在真实环境运行；同时看**指标达成**与
   **业务采纳**（用户实际使用/流程融入）。不通过 → **优化迭代**回环（改产品/
   改特征/改流程），再试点。通过 → 进入规模化。
5. **规模化与运营**：分批推广（每批带验收）→ 上线运营（监控+值班+兜底预案，
   引用 fde-risk-human-fallback）→ 固定节奏运营反馈（月度）→ 持续优化。
6. **输出契约**：执行状态板：四步建设状态、两道闸门判定记录（数据+结论）、
   回环日志（问题/修正/效果）、规模化批次表、运营反馈节奏与改进清单。

## B — Boundary (边界)

- **不要**用于：没有成功指标的"直接试试看"（先回方案定义）；纯POC演示（没有
  试点闸门诉求的探索性验证）。
- **失败模式**：两道闸门合并成一道（技术达标=上线，业务采杀死项目）；规模化
  一步到位（无分批验收）；上线即失管（没有运营反馈回环，效果衰减无人知）。
- **作者盲点**：图未定义"达标/通过"的量化判据（由方案定义阶段承接，执行时若
  上游没给，按E段补问）；未涉及规模化后的组织变更管理（SOP/培训），大规模
  推广时需自行补充。

## Purpose

AI试点怎么设计和验收；试点效果不达标怎么修正；AI项目怎么从试点走向规模化推广。本技能是FDE执行落地阶段的主执行流程：环境→能力→联调→试点，两道闸门（技术验收/业务验收）不过就回环修正；通过后规模化+上线运营+反馈优化。

## Troubleshooting

引自 B 段失败模式：

- **两道闸门合并成一道**（技术达标=上线，业务采杀死项目）：牢记效果达标是技术验收（实验室），试点通过是业务验收（现场），两道独立的门缺一不可。
- **规模化一步到位**（无分批验收）：按E段第5步分批推广，每批带验收。
- **上线即失管**（没有运营反馈回环，效果衰减无人知）：固定节奏（月度）运营反馈+持续优化，上线不是终点。
- **能力构建期间缺陷反复**：走问题修正回环并逐条记录（问题/修正/验证），不得跳过记录。

- 上游成功指标与测量方式判据（联调/试点闸门判定引用之）。
