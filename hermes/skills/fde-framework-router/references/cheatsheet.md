# 决策规则速查 — 一图讲透 FDE：企业AI落地完整框架（v2 扩展版：+ Lab0 产品化 + Varick 实战 playbook）

| 能力 | 一句话规则 |
|---|---|
| FDE三阶段落地主流程（机会发现→方案定义→执行落地） | 先判断值不值得做，再定义到可行，最后试点通过才规模化——三道闸门顺序不可跳。 |
| 机会发现：场景池与'是否值得做'闸门 | 五个入口喂场景池，逐个过'是否值得做'——不值得就暂缓观望，不硬上。 |
| 方案定义：六项产出与'是否可行'闸门 | 价值、优先级、成功指标、流程拆解、数据准备、方案设计六项齐了且判断可行，才开建。 |
| 执行落地：试点闸门、回环修正与规模化 | 环境→能力→联调→试点，两道闸门不过就回环修正；通过后规模化+上线运营+反馈优化。 |
| 风险处理与人工兜底旁路 | 每个AI环节都预设风险处理与人工兜底两条退路，AI故障不允许击穿业务。 |
| 三类回环：问题修正、优化迭代、运营反馈 | 构建期靠问题修正，试点期靠优化迭代，运营期靠运营反馈——三种回环别混用。 |
| 流程映射与基线：human API、过程挖掘与'先基线后建设' | 先建 human API：访谈与过程挖掘对账出真实流程，回环按钱和时间计价，KPI 基线在动工前锁定。 |
| 工作流四分法：delete / plain code / agent / human | 每步只贴一个标签：删除、纯代码、智能体、人工——先删 waste 再建 agent，高风险步永远留人工。 |
| 按系统落地与按结果销售：build-in-place + outcome pricing | agent 长在客户已有的系统里（零再培训），价值按三桶卖给对应买家，基线在先、before/after 说话。 |
| AI-FDE 产品化：把 FDE 作为产品交付（Lab0 模式） | FDE 正在被产品化：可模板化的交付环节变成软件，人的价值向判断与关系两端移动。 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
